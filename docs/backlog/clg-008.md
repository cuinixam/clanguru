# [CLG-008] Clearer doc block error messages

**Status**: Open
**Priority**: Low
**Issue**: #15
**Component**: `src/clanguru/doc_generator.py`

**Summary**:
As an author of C/C++ doc comments, I want a doc block error to name the file and the valid template fields, so that I can find and fix the faulty placeholder without guessing.

**Description**:
Two doc block error messages in 0.22.0 still leave the author guessing.

1. A block above a declaration names the declaration, not the file.

   ```c
   /** @docs {{ gtest.test }} @enddocs */
   void helper(void) {}
   ```

   fails with `Undefined template variable in doc block of 'helper:3': ...`. `helper` is the function name, but `helper:3` reads like a file path, and the file is not named. A free block already names the file (`gap.cc:3`). Proposal: name the file and add the declaration, for example `helper.cc:3 (helper)`. The location is built in `_collect_comment_contents` from `name` and `token.cached_line`.

2. A wrong gtest field shows an internal class name.

   ```cpp
   /** @docs {{ gtest.tset }} @enddocs */
   TEST(Suite, Case) {}
   ```

   fails with `'clanguru.doc_generator.GTestInfo object' has no attribute 'tset'`. Proposal: `'gtest' has no attribute 'tset'. Available: gtest.suite, gtest.case, gtest.test`. The error is raised in `_render_doc_template`.

**Acceptance Criteria**:
- [ ] An error in a block above a declaration names the file, the line and the declaration
- [ ] An unknown `gtest` field names `gtest` and lists the available fields
- [ ] All existing tests continue to pass
