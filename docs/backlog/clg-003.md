**Reason**:

It is also not clear how the output fits next to the existing per-file docs. The `analyze` Excel report already lists the provided symbols of each object and the objects that use them. Open a new item with a concrete use case if the need comes back.

**Summary**:
As a component developer, I want a document that lists my component's provided and required interfaces, so that I can trace my tests to those interfaces.

**Description**:
`analyze` already splits each object's symbols into provided and required, and `mock` uses the required symbols of a partial-link object. clanguru drops this data after it writes the report or the mock. The new output builds a `DocStructure` from it, one section per component with provided and required symbols, and renders it with the existing Markdown, MyST and RST formatters.

To decide before starting:
- symbol names only, or signature and doc comment from the parsed sources;
- an output mode of `analyze` (reuses its compilation database and directory grouping) or a separate command.

"Component" means the same directory grouping as in the `analyze` graph.

**Acceptance Criteria**:
- [ ] For each component, the document lists provided and required symbols in separate sections
- [ ] The document renders in Markdown, MyST and RST through the existing formatters
- [ ] Components are grouped the same way as in the `analyze` graph
- [ ] The feature is documented
- [ ] All existing tests continue to pass
