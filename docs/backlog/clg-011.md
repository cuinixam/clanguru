# [CLG-011] Fast skipped-code check for sources with large headers

**Status**: Done
**Priority**: High
**Component**: `src/clanguru/cparser.py`

**Summary**:
As a user of `docs` on a large embedded code base, I want the skipped-code check to cost the same as in 0.20.0, so that the source documentation of a big project builds as fast as before.

**Description**:
0.22.0 ignores `@docs` blocks in code that the preprocessor skips (CLG-007). `CLangParser._get_skipped_ranges` asks libclang for the skipped ranges of all files of the translation unit with `clang_getAllSkippedRanges` and keeps the ones of the source file by calling `Path.resolve()` on each range.

AUTOSAR-style headers such as `MemMap.h` are included many times and have many `#if` branches, so one source can have hundreds of thousands of skipped ranges in its headers. Each `Path.resolve()` is a file system call. In a real project, `docs` for one source took 17 to 138 s with 0.22.0, against about 1.5 s with 0.20.0. The profile showed 242,805 `resolve()` calls for one source, which took 24 of its 50 s.

Fix: `clang_getSkippedRanges(tu, file)` returns the skipped ranges of the source file only, so no range is filtered or resolved.

**Acceptance Criteria**:

- [x] The cost of the skipped-code check does not grow with the skipped ranges of the included headers
- [x] `@docs` blocks in skipped code of the source file are still ignored
- [x] The generated docs of the real project are unchanged
- [x] All existing tests continue to pass

**Tasks**:

1. Use `clang_getSkippedRanges` for the source file in `_get_skipped_ranges`. File: `src/clanguru/cparser.py`.
2. Test that the skipped ranges of a header are not resolved one by one. File: `tests/test_doc_generator.py`.
