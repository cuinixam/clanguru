# [CLG-017] Render from a user template folder and pick defined or undefined symbols

## Summary

As a tool author who builds on clanguru, I want to give `clanguru mock` my own template folder and choose whether it renders the symbols an object defines or the ones it leaves undefined, so that I can generate other outputs than gmock mocks, such as a Python ctypes binding or C trampolines, without a clanguru release for each one.

## Description

`clanguru mock` finds the symbols an object leaves undefined, recovers their declarations with libclang and renders them with the gmock templates. The renderer is chosen from a fixed mock type, where only gmock is implemented, and the Jinja loader reads only the templates shipped in the package. A `TemplateRenderer` interface already exists in the code, but a user cannot plug into it from the command line.

yanga wants to test a component or a variant from pytest through a shared library. For that it needs two more outputs from the same symbol and declaration data: a Python module that declares the functions the library defines (for ctypes), and one C trampoline per undefined symbol that forwards the call to a function pointer set from Python. Both are templates; neither needs a change to the parser.

## Scope decisions

- **A template folder option.** Every `*.j2` template in the folder is rendered once with the same context the gmock templates get (functions, variables, headers, missing symbols). The output name is the template name without `.j2`, itself rendered with the context, so `{{ filename }}_binding.py.j2` writes `<filename>_binding.py`. With a template folder the mock type is not used.
- **A symbol choice.** A boolean flag with a positive name (`--defined-symbols/--no-defined-symbols`, default off) renders the symbols the partial-link object defines instead of those it needs. The object analyzer already reads both sets from `nm`.
- **Resolved types.** Today a parameter's type is passed as written in the source (`uint8_t`, `RGBColor`). A ctypes template must map every type to a C base type, so each return type, parameter and variable also carries its type with all typedefs resolved (libclang's canonical type).
- **The struct and enum types the signatures use,** with their fields (name and resolved type) and their constants (name and value), so a template can write a ctypes `Structure` for `RGBColor` and constants for `PowerState`.
- **gmock stays the default.** Without a template folder the command writes exactly what it writes today.
- **Out of scope:** shipping the ctypes or trampoline templates in clanguru (they belong to the tool that uses them), filtering defined symbols by header, unions, bit fields and function-pointer types in the context.

## Acceptance criteria

- [ ] With a template folder, `clanguru mock` writes one output file per template in that folder, rendered with the functions, variables, headers and missing symbols
- [ ] With the defined-symbols choice, the rendered functions are those the object defines, with their declarations from the sources
- [ ] A parameter declared as `uint8_t` or as a typedef of an enum reaches the template also as its resolved base type
- [ ] A struct passed or returned in a rendered function reaches the template with its fields, and an enum with its constants
- [ ] Without the new options, the generated gmock files are unchanged
- [ ] The usage docs describe both options and the template context
- [ ] `pypeline run` is green
