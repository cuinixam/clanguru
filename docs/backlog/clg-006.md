# [CLG-006] Format-neutral tags for sphinx-needs items

**Status**: Open
**Priority**: Low
**Component**: `src/clanguru/doc_generator.py`

**Summary**:
As an author of C/C++ doc comments, I want one tag for a sphinx-needs item that works for RST and MyST output, so that I don't rewrite my comments when I switch the output format.

**Description**:
Today a needs item in a comment is written in the output syntax, inside an `@rst` or `@md` block. A new block, for example `@need test <id> ... @endneed`, carries the directive name, the ID, the options and the content. The formatter renders it as an RST directive or a MyST fence. Jinja templating runs before the translation, as it does today for extracted blocks.

To decide before starting: the option syntax inside the block, and whether any directive name is accepted.

**Acceptance Criteria**:
- [ ] A `@need` block renders as a valid RST directive in RST output
- [ ] The same block renders as a valid MyST directive in MyST output
- [ ] Jinja placeholders inside the block are resolved
- [ ] The tag is documented
- [ ] All existing tests continue to pass
