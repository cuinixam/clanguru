# [CLG-016] Source links in the generated docs

## Summary

As the author of a C/C++ project whose generated source docs sit next to a coverage report, I want each documented declaration to carry a link to its file and line, so that a later build step can turn it into a link to that line in the coverage report.

## Description

`clanguru docs` writes one section per declaration: its doc comment and its code. Nothing in that output says where the declaration lives, so a reader who wants its coverage has to find the file in the coverage report by hand. clanguru already knows the file and the first line of each declaration.

This item adds a plain Markdown link with a `source:` URL to each declaration section. clanguru does not resolve it: what the link points to (a coverage page, an editor) is decided later by the tool that builds the report. This is the first part of a change across clanguru, yanga and SPLed; the design and the checks against a built report are in the planning vault's epic SB-004.

## Scope decisions

- **Link format.** `[<path>:<line>](source:<path>#<line>)`, for example `[components/light_controller/src/light_controller.c:42](source:components/light_controller/src/light_controller.c#42)`. The shown text and the link carry the same path; the line goes in the fragment. clanguru knows nothing about coverage, Sphinx or URLs.
- **Options.** `--source-links/--no-source-links`, off by default so today's output does not change, and `--project-root PATH`. With the switch on, the path is relative to the project root, or absolute when no root is given.
- **Formats.** MyST and plain Markdown only. reStructuredText stays out: it is unknown how docutils treats an unknown URL scheme.
- **Placement.** After the doc content and the code block of a declaration section. A doc block without code (a free doc comment at file scope) gets its link after the doc text, pointing at the first line of that comment.
- Out of scope: resolving the link, any knowledge of the coverage report, reStructuredText.

## Acceptance criteria

- [ ] `clanguru docs` without `--source-links` writes the same output as before
- [ ] With `--source-links` and `--project-root`, every declaration section in MyST and in Markdown output ends with a `source:` link whose path is relative to the project root and whose fragment is the declaration's first line
- [ ] With `--source-links` and no `--project-root`, the link path is absolute
- [ ] A free doc comment at file scope gets its link after the doc text, pointing at the comment's first line
- [ ] The two options are documented in clanguru's docs
- [ ] `pypeline run` is green
