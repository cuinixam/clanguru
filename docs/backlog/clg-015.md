# [CLG-015] ✅ DONE - analyze uses host nm on Windows cross toolchains

**Status**: Done (2026-11-06)
**Priority**: High
**Component**: src/clanguru/object_analyzer.py

**Summary**:
As a developer building with a cross toolchain on Windows, I want `clanguru analyze` to use the toolchain's nm, so that the objects dependency report works for my target.

**Description**:
On Windows the compiler in `compile_commands.json` ends in `.exe` (for example `riscv64-zephyr-elf-gcc.exe`). `NmExecutor.for_compiler` matches the `<prefix>-gcc` pattern against the full file name, so the match fails and it falls back to the host `nm`. The host `nm` cannot read the RISC-V objects and exits with code 1, which fails the whole `analyze` run. The toolchain's `riscv64-zephyr-elf-nm.exe` sits next to the compiler but is never tried.

**Acceptance Criteria**:
- [x] `NmExecutor.for_compiler` returns `<prefix>-nm.exe` when it sits next to a `<prefix>-gcc.exe` compiler.

Seen in spledy (`yanga run --target report`, Zephyr esp32h2 variant) with clanguru 0.23.1.
