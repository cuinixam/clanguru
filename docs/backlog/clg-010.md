# [CLG-010] Doc blocks of prototypes inside `extern "C"`

**Status**: Open
**Priority**: Low
**Component**: `src/clanguru/cparser.py`

**Summary**:
As an author of C/C++ doc comments, I want `docs` to read the blocks above a prototype inside an `extern "C"` block of a header, so that a C header documents its functions also when a C++ source includes it.

**Description**:
CLG-009 reads the blocks above the declarations of a function in an included header. It only searches the top-level nodes of the translation unit. A C header that is meant for C++ too wraps its prototypes in a linkage block:

```c
/* foo.h */
#ifdef __cplusplus
extern "C" {
#endif

/** @docs Calculates the checksum. @enddocs */
int Foo_Checksum(int value);

#ifdef __cplusplus
}
#endif
```

In a C++ source the prototype sits under a `LINKAGE_SPEC` node, not at the top level. Its blocks are dropped without a message. In a C source `__cplusplus` is not defined, so the same header works.

Found in the review of the CLG-009 pull request.

**Acceptance Criteria**:
- [ ] In a C++ source, blocks above a prototype inside `extern "C" { }` of an included header appear in the section of the function
- [ ] The single `extern "C"` form without braces (`extern "C" int foo(void);`) is covered too
- [ ] The behaviour is documented
- [ ] All existing tests continue to pass
